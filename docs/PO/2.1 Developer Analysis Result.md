## 2. Analisis Kesesuaian Fungsional & Batasan Sistem (Scope Compliance)

Merujuk pada dokumen `1. Project-Overview.md`:

### 2.1 Batasan In-Scope (4 Modul Keputusan Utama)

1. **Modul 1: Executive Revenue Overview**
   - **Rencana:** Menampilkan Total Revenue, Total Volume Orders, AOV, dan tren penjualan bulanan/tahunan.
   - **Realisasi:** **Lengkap & Berfungsi Sangat Baik.**
     - Backend: `GET /api/dashboard/summary`, `GET /api/sales/monthly`, `GET /api/sales/yearly`.
     - Frontend: Visualisasi grafik batang/garis interaktif di halaman `Overview.jsx` dan `SalesAnalysis.jsx`.
2. **Modul 2: Order Fulfillment & Logistics Health**

     - Developer malah membuat modul tambahan `EmployeeAnalysis.jsx` (`/api/employees/performance` dan `/api/employees/sales`) yang menampilkan kinerja representatif penjualan.
3. **Modul 3: Inventory & Stock Health**
   - **Rencana:** Memantau stok vs permintaan per kategori produk untuk mendeteksi *dead-stock* atau risiko *stockout*.
   - **Realisasi:** **Sebagian Sesuai.**

4. **Modul 4: Customer Intelligence & Demographics**
   - **Rencana:** Menampilkan 10 pelanggan pembayar terbesar (*Top Spenders*), limit kredit, dan sebaran geografis pembeli (negara/kota).
   - **Realisasi:** **Lengkap & Berfungsi Sangat Baik.**

     - Frontend menampilkan daftar top customer dan peta/grafik sebaran negara di `CustomerAnalysis.jsx`.

## 3. Analisis Praktik Pengkodean Aman (Secure Coding & SQL Injection)

Kebijakan pada dokumen `1.2 Risk.md` menetapkan **ZERO TOLERANCE (0)** terhadap celah SQL Injection (SQLi).

### 3.1 Evaluasi Kueri Backend (`app/backend/app/Http/Controllers/Api/`)
Pemeriksaan kode terhadap seluruh Controller (`CustomerController`, `DashboardController`, `EmployeeController`, `ProductController`, `SalesController`) menunjukkan:

1. **Penggunaan Laravel Fluent Query Builder:**
   Semua kueri basis data dibangun menggunakan abstraksi `DB::table(...)` yang memanfaatkan *Prepared Statements* (PDO binding) bawaan Laravel.
   ```php
   // Contoh implementasi di SalesController.php
   $sales = DB::table('orders')
       ->join('orderdetails', 'orders.orderNumber', '=', 'orderdetails.orderNumber')
       ->whereNotIn('orders.status', ['Cancelled'])
       ->selectRaw('EXTRACT(YEAR FROM orders.orderDate) AS year')
       ->selectRaw('SUM(orderdetails.quantityOrdered * orderdetails.priceEach) AS revenue')
       ->selectRaw('COUNT(DISTINCT orders.orderNumber) AS order_count')
       ->groupByRaw('EXTRACT(YEAR FROM orders.orderDate)')
       ->orderBy('year')
       ->get();
   ```
2. **Tidak Ada Interpolasi String Mentah:**
   Tidak ditemukan adanya konkatenasi variabel pengguna (`$request->input()`) ke dalam klausa SQL (`DB::raw` atau `selectRaw`).
3. **Attack Surface Sangat Minimal:**
   Seluruh endpoint analitik tidak menerima parameter kueri bebas dari client (*zero parameter input*), sehingga secara struktural **kebal terhadap vektor serangan SQL Injection tradisional**.

## 4. Analisis Manajemen Kredensial & Kebocoran Rahasia (Secrets Hygiene)

Berdasarkan aturan `1.2 Risk.md` terkait pencegahan kebocoran rahasia (*Secrets Leak*):

1. **Pemisahan Konfigurasi Lingkungan:**
   - File konfigurasi lokal `.env` telah dimasukkan ke dalam `.gitignore` sehingga tidak terlacak (*untracked*) ke dalam version control.
   - File template `.env.example` hanya berisi kredensial dummy tanpa password nyata (`DB_PASSWORD=`).
2. **Pembersihan Hardcoded Keys:**
   - Tidak ditemukan database credentials, token API, atau private keys yang ditulis secara statis (*hardcoded*) di dalam source code PHP maupun JavaScript.
