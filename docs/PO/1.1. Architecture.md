

## 1. Rincian Komponen Arsitektur (Component Architecture)

### 1.1 Presentation Tier (Frontend Web UI)
Frontend berfungsi sebagai antarmuka visual interaktif yang menyajikan agregasi data dan grafik tren keputusan bisnis:
* **Framework & Core:** **React 19** dibangun di atas build-tool modern **Vite 8**.
* **Routing:** `react-router-dom v7` dengan navigasi modular (*App Shell Layout*):
  - `/overview`: Executive Overview & Ringkasan KPI.
  - `/sales`: Analisis Penjualan Bulanan, Tahunan, dan Sebaran Negara.
  - `/products`: Analisis Produk Terlaris (*Top Selling*), Kurang Laris (*Low Selling*), dan Profitabilitas.
  - `/customers`: Top 10 Pelanggan (*Top Spenders*), Sebaran Negara, dan *Customer Lifetime Value (LTV)*.
  - `/employees`: Evaluasi Performa Representatif Penjualan (*Sales Reps*).
* **Visualisasi Data:** Menggunakan **Recharts** dan **Chart.js** untuk grafik batang (*bar chart*), garis tren (*line chart*), dan kartu metrik (*StatCards*).
* **Komunikasi Data:** Library **Axios** dengan konfigurasi base URL dinamis via `import.meta.env.VITE_API_URL`.
* **Prinsip Keamanan Frontend:**
  - Bersifat murni *read-only* (tidak menyediakan form input mutasi data seperti tambah/edit/hapus).
  - Sanitasi rendering bawaan React untuk mencegah *Cross-Site Scripting (XSS)*.
  - Penanganan status loading dan error yang aman (*graceful error handling*) tanpa membocorkan stack trace.

---

### 2. Application Tier (Backend RESTful API)
Backend bertanggung jawab mengeksekusi kueri analitik, melakukan kalkulasi metrik bisnis, dan menyajikan data dalam format JSON standar:
* **Framework:** **Laravel 13** berbasis **PHP 8.4**.
* **Karakteristik Endpoint:** Seluruh 12 endpoint hanya melayani metode **`GET`** (Zero Attack Surface for Data Mutation):
  - Ringkasan Eksekutif: `/api/dashboard/summary`
  - Penjualan: `/api/sales/monthly`, `/api/sales/yearly`, `/api/sales/by-country`
  - Produk: `/api/products/top-selling`, `/api/products/low-selling`, `/api/products/profitability`
  - Pelanggan: `/api/customers/top`, `/api/customers/by-country`, `/api/customers/value`
  - Karyawan: `/api/employees/performance`, `/api/employees/sales`
* **Data Access Layer:** Menggunakan **Laravel Fluent Query Builder** (`DB::table(...)`) dengan *Prepared Statements* (PDO Binding) penuh.
* **Prinsip Keamanan Backend:**
  - **Zero Tolerance SQL Injection:** Tidak ada interpolasi string SQL mentah (`DB::raw` dinamis) dari input pengguna.
  - **CORS Protection:** Pengaturan header CORS ketat yang hanya mengizinkan origin frontend terdaftar.
  - **Pencegahan Data Exposure:** Pemilihan kolom (*column projection*) eksplisit pada kueri; tidak melakukan `SELECT *` sembarangan pada tabel yang memuat data sensitif.

### 3. Data Tier (MySQL Database)
Data Tier menjadi fondasi penyimpanan data historis transaksi dan operasional perusahaan:
* **Engine:** **MySQL 8.x / MariaDB 10.4+**.
* **Skema Basis Data:** Basis data relasional `classicmodels` yang terdiri dari 8 tabel utama:
  1. `customers`: Data profil pelanggan, batas kredit (*creditLimit*), dan wilayah negara.
  2. `orders`: Data transaksi pesanan, tanggal order, dan status pengiriman.
  3. `orderdetails`: Rincian item pesanan, kuantitas order, dan harga satuan (*priceEach*).
  4. `products`: Katalog model kendaraan, stok gudang (*quantityInStock*), dan harga beli/jual (*buyPrice*, *MSRP*).
  5. `productlines`: Deskripsi kategori lini produk (*Classic Cars, Motorcycles, Planes*, dll.).
  6. `employees`: Struktur organisasi staf dan representatif penjualan (*salesRepEmployeeNumber*).
  7. `offices`: Lokasi kantor cabang regional di seluruh dunia.
  8. `payments`: Catatan pembayaran transaksi faktur.
* **Prinsip Keamanan Basis Data:**
  - **Prinsip Hak Akses Minimal (Least Privilege):** Pengguna database aplikasi DSS di lingkungan produksi wajib dibatasi hanya memiliki hak akses `SELECT` (`GRANT SELECT ON classicmodels.* TO 'dss_user'@'%';`).
  - **Isolasi Port:** Port basis data (3306) **dilarang diekspos ke publik** di lingkungan kontainer/produksi; hanya dapat dijangkau oleh kontainer backend melalui jaringan internal.


## 3. Alur Data


1. **Inisiasi Permintaan:** Pengguna membuka modul pada dashboard (misal: *Sales Analysis*).
2. **REST API Request:** Frontend memicu request HTTP `GET /api/sales/monthly` melalui Axios.
3. **Eksekusi Kueri Analitik:** Controller Laravel mengeksekusi kueri teragregasi (`SUM`, `COUNT`, `GROUP BY`) ke database MySQL dengan prepared statement.
4. **Transformasi JSON:** Database mengembalikan dataset relasional; backend memformatnya menjadi struktur JSON ringkas dan aman.
5. **Visualisasi Dinamis:** Frontend menerima data JSON, memetakan ke state React, dan merender grafik visual interaktif (Recharts).
